# 自动标签部署与就绪验证

正式部署默认开启自动分析，无需额外设置环境变量。配置可用模型/凭据并启用规则后，会按 CRON 分析账目，可能向供应商发送经隐私处理的内容并产生费用；不会自动审批建议。健康接口成功仍不等于模型或规则已就绪。

设置页的“自动分析开关”保存在 SQLite `setting` 中。关闭后立即撤销规则调度，重启或重建容器后仍保持关闭；重新开启会注册已启用的规则。部署层显式设置 `PAAM_AUTOTAG_REAL_ANALYSIS=0` 时，页面不能越过该限制，需先修改容器启动配置并重建。开启规则可能产生模型费用，建议仍需人工审批。

如需明确关闭，在应用进程启动环境设置 `PAAM_AUTOTAG_REAL_ANALYSIS=0`。显式 `1` 仍可用于启用：

```text
PAAM_AUTOTAG_REAL_ANALYSIS=1
PAAM_AUTOTAG_SYNTHETIC_ACCEPTANCE=0
```

开关在模块加载时读取。Docker 已创建容器的环境不会因 `docker restart`、宿主终端 `export` 或 `docker exec -e` 改变。修改 Compose/service 的持久配置并重新创建应用容器；手动部署也须创建替代容器。不要同时运行两个写入同一 SQLite 的应用实例。

旧部署若显式保留 `PAAM_AUTOTAG_REAL_ANALYSIS=0`，升级后仍保持关闭；删除该覆盖或改为 `1` 并重建容器。`Dockerfile.pirc9` 是正式入口，遵循默认开启；`Dockerfile.pirc24-ui` / `serve_m2_ui.py` 是纯虚构演示入口，刻意关闭真实分析，不能作为正式部署入口。显式请求虚构验收时不会默认开启真实分析；两者显式同时启用仍拒绝启动。

## CRON 输入约定

规则接受 5 段 `分 时 日 月 周`，或 6 段 `秒 分 时 日 月 周`（秒在最前）。执行时区固定为香港 `Asia/Hong_Kong`。数字星期按传统 crontab 解释：`0` 和 `7` 是周日，`1` 至 `6` 是周一至周六；也接受 `mon` 至 `sun` 英文缩写，不区分大小写。保存时数字星期会转换成星期名，避免 APScheduler 3.x 将 `0` 误当周一。

字段支持 `*`、逗号列表、范围 `a-b`、步长 `*/n` 和范围步长 `a-b/n`，实际取值由各字段范围限制。例如 `*/5 * * * *` 每 5 分钟，`0 9 * * 1-5` 工作日 09:00，`15 30 9 * * mon-fri` 工作日 09:30:15。星期的 `*/2` 从周日开始。无法产生下一次执行时间的组合（例如 2 月 31 日）在保存规则时会被拒绝。`@daily`、Quartz 的 `?`/`#` 和 7 段年份表达式不属于此接口。

本应用沿用 APScheduler 的“所有指定字段同时满足”语义：若“日”和“星期”都不是 `*`，两者是 AND，不是部分 Unix cron 实现的 OR。为避免误触发，通常只限定其中一个。

## 切换步骤

新建正式 Docker 部署可直接使用以下命令，不需要附加自动分析开关（示例只用于新部署，不覆盖已有容器）：

```text
docker build -f src/report/Dockerfile.pirc9 -t paam:production .
docker run -d --name paam-production --restart unless-stopped -p 127.0.0.1:8765:8765 --mount type=volume,source=paam-production-data,target=/data paam:production
```

仍须配置可用的凭据存储、保存模型密钥并启用规则；默认开启调度不会绕过这些条件，也不会自动添加模型或规则。

1. 核对镜像 revision、原容器入口/命令、端口、数据库卷和凭据卷；用 SQLite backup API 创建一致性备份，限制备份权限。不要打印或复制 API Key 到配置文件。
2. 保留用户已选规则、CRON、游标、申请和人工标签。创建使用原镜像/卷/凭据服务的新容器，只修改上述两个开关；保留其他环境与部署参数。
3. 停止旧容器后启动新容器。失败时先停新容器，再启动保留的旧容器；无需恢复旧数据库覆盖新数据。不要删除原卷。
4. 运行下面的只读检查。它在开关关闭、Worker 不健康、无启用规则、规则未注册或被阻塞时返回非零；不会触发模型或修改数据。

```powershell
python src/script/verify_auto_tag_runtime.py --base-url http://127.0.0.1:18775
```

5. 等待自然 CRON，观察规则游标、累计统计、安全诊断和新待审申请。`ready=true` 只证明调度已就绪，不证明供应商请求或分类正确。超时可能让供应商已执行但本地未获结果；以诊断、申请和游标共同核对，不将超时当作“无建议”。
6. 真实模型产生的申请默认保持待审。审批验收可在独立数据库副本执行，核对标签生效、其他 View 不变、金额与 Allocation 不变。未经用户选择不要审批正式库申请。

重启后再次执行步骤 4/5，确认设置、申请和游标恢复。新导入自动进入后续 CRON；无需重导旧账单或重置游标。

## 模型供应商、代理与模型目录

模型编辑器提供硅基流动、DeepSeek 官方、OpenCode Console 和自定义 OpenAI Chat Completions 兼容地址。预设只填入 HTTPS API 地址；用户仍须选择模型并配置相应供应商的 API Key。OpenCode 预设使用 Console 推理 API，不使用 OpenCode Go 订阅；Go 的用途和请求要求与此处的账目分类不同。

“获取模型列表”只向供应商发送一次只读 `GET /models`（OpenCode 使用其公开的 `/inference/v1/models`），不会发送账目或触发推理。若编辑已保存模型且地址、代理未变，可使用已保存的 API Key；若修改地址或代理，须在表单中重新填写 API Key 才能获取目录，避免把旧密钥发送到新目标。列表仅辅助输入 LiteLLM 模型名，不代表模型已授权、接口兼容或分类成功。OpenCode 的公开列表混合多个 API 家族，本界面只列出已确认的 Chat Completions 模型；其他类型不适用于当前分类调用。

每个模型可填 `http://` 或 `https://` 代理地址；该配置优先于部署级 `PAAM_LLM_PROXY`。容器内的 `127.0.0.1` 是容器自身，宿主机代理通常应填写 `http://host.docker.internal:<端口>`，并确保宿主机代理允许容器访问。无代理配置时本应用继续直连，刻意不自动继承容器的 `HTTP_PROXY` / `HTTPS_PROXY`，以免账目数据走未经确认的代理。代理 URL 不允许用户名、密码、路径或查询参数；有鉴权要求的代理当前不支持。部署级代理需要在容器创建时设置并重建容器，例如 `PAAM_LLM_PROXY=http://host.docker.internal:7890`。仅改代理不会重置规则游标或取消待审申请。

模型“测试真实连接”是一次有上限的真实推理，会发送最小探测消息，不读账目；超时上限为 60 秒，未配置模型超时时默认 30 秒。分类调用默认 60 秒，可在模型高级参数中调整；超时只表明本地没有收到结果，不能判断供应商是否已经执行或计费。先用模型列表验证目录和网络，再测试真实连接，最后观察自然 CRON 的诊断与待审申请。不能仅凭目录成功认定推理可用。

选择供应商和模型前请核对其隐私条款与数据保留政策。OpenCode Console 的部分免费模型公开声明会记录输入或用于改进模型，含财务数据的自动分类不应盲目使用这类模型。
