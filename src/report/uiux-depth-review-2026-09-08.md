# UI/UX 深度操作评审

2026-09-08，接续 [需求核对报告](ui-review-2026-09-08.md)。

结论：当前界面的主要短板是操作流程和状态表达。功能按技术模块堆在页面上，但用户完成“看懂账目、找到问题、处理后继续工作”的路径不够连贯。桌面大屏上外观相对统一，窄窗口和手机端存在明显布局错误；保存失败、导航返回和导入文件变更时，也缺少保持用户意图的处理。

## 如何评审

实际驱动本机 Edge 点击五页导航、搜索、清空、翻页、选择标签、保存、Escape 关闭、候选详情、关闭、撤销和拒绝建议；使用浏览器后退，切换到 390、740、768、1440px 宽度，观察截图和控件位置。补充了两项仅作用于测试浏览器的失败模拟：标签保存返回 500、标签定义加载返回 500。未修改服务端以制造失败。

上一轮覆盖多格式导入、重复/转移处理及数据库翻页。本轮继续使用隔离体验数据库，最后为验证文件选择一致性新增一条 ux-A 测试流水，原始账单总数变为 69 条。未改业务代码，也未进行真实用户访谈、屏幕阅读器全流程或正式无障碍合规认证。

## 本轮新确认的问题

| 优先级 | 操作与实际结果 | UX 影响 | 改善方向 |
| --- | --- | --- | --- |
| P1 | 预览 ux-A.csv → 改选 ux-B.csv → 确认。文件框显示 B，网络提交的却是 A，反馈“已导入 1 个文件”。 | 用户看到的选择和实际执行不一致，可能漏导当前文件。 | 文件或平台变化时使预览失效；确认区明确列出即将导入的文件，并绑定预览版本。 |
| P1 | 768px 窗口下数据页仍用两列，右侧筛选卡片被挤成窄条，输入框和文字覆盖。页面宽度达到 849px。 | 常见窄窗口中无法正常阅读和操作筛选。 | 按主内容可用宽度切布局，约束子项最小宽度；统一两份 CSS 的断点。 |
| P1 | 模拟标签保存失败：弹出“模拟保存失败”，关闭提示后编辑弹窗已移除。 | 已选择的内容丢失，用户必须重新打开、重新选择，无法直接重试。 | 保存成功再关弹窗；失败在弹窗内显示原因并保留输入。 |
| P1 | 已看过标签页，切出后模拟标签加载失败，再进入。旧标签列表仍显示，只有 JS 错误，没有页面错误提示。 | 用户不知道数据未更新，也没有重试入口。 | 页面明确区分加载、已更新、失败和旧数据；提供重试。 |
| P2 | 汇总 → 数据 → 浏览器后退，返回 about:blank；页面之间 URL 一直相同。 | 后退无法回到应用内上一步，无法分享或收藏当前筛选页面。 | 为页签与筛选建立 URL/历史状态。 |
| P2 | 搜索后切其他页再回来，搜索被清空。 | 复核过程中失去工作位置。 | 保留搜索、筛选、排序、页码和适当的滚动位置。 |
| P2 | 20 条/页点击“下一页”，页码变为 2，但 scrollY 仍为 1415，表头位于视口上方约 838px。 | 用户落在新一页末尾，需要往上滚才能从第一条开始看。 | 翻页后定位列表顶部；分页控件可在表格上下两端提供。 |
| P2 | 手机 390px 数据页的表头约在文档 1492px 处。 | 在 844px 高屏幕中，第一屏看不到流水；高频看账操作让位给低频导入和完整筛选。 | 流水作为主体，导入独立打开，高级筛选折叠。 |
| P2 | 手机候选区可视宽 320px，表格内容约 730px。 | 对照证据和处理按钮要反复横拖；类别被逐字挤成竖排。 | 小屏改为候选卡片，证据和决策在同一列；桌面保留对照布局。 |
| P2 | 拒绝重复建议后状态变为 duplicate_rejected，但筛选没有该选项；“已忽略”显示 0 条。 | 已处理记录不易找回，用户不清楚“拒绝”和“忽略”的关系。 | 为拒绝、忽略、稍后、已确认提供清晰中文状态和筛选。 |
| P2 | 搜索不存在的交易，只有“没有流水”、0 条和禁用分页。 | 不能明确区分“从未导入”和“当前条件无结果”。 | 文案改为“没有符合条件的流水”，就近给出清空筛选。 |

文件选择错误定位在 `app/static/workspace-next.js` 的 `previewImport`、`confirmImport`：缓存 `state.pendingImport` 后，文件控件变化没有使缓存失效。保存失败问题在 `assignTag` 的 close 回调：不论保存成功或失败都会移除 dialog。导航状态问题在 `setPage`：只写 localStorage，没有历史记录。

## 各页面的 UI/UX 判断

### 汇总

卡片、字体和留白比较统一，金额容易找到。但当前只有静态金额和按日表格，没有日期范围、待复核入口，也不能从金额进入对应流水。用户看到“支出 1,960 元”后，要自己去另一页重建查询。“按日趋势”用表格展示不违反已有需求，但缺乏快速识别变化的能力。

建议：优先补统计范围、计数口径和金额下钻；把“待复核多少条”放在能继续操作的位置。图表属于后续体验优化，不应替代正确统计和明细追溯。

### 导入与数据

这里承担了导入、复杂筛选、账目浏览、标签编辑四种任务，却没有明显的主次。左右卡片等高导致导入卡片大片空白；常驻文件输入和 ZIP 密码抢占空间；标签、来源和账户信息层层堆在每行里，默认 50 条会形成很长页面。

建议：主区先展示流水与紧凑搜索栏；“导入账单”作为明确操作进入独立面板，按“选平台/文件 → 检查预览 → 结果”组织。把 ZIP 密码限制在实际需要它时出现。展示已应用筛选，让用户知道当前看到哪部分数据。

### 标签管理

新建视图的输入框占据半页，已有标签却只是不可操作的药丸形文本。外观像可点击选项，实际没有管理行为。用户还被要求理解“同视图互斥”“系统名”“JSON”等内部概念。

建议：默认把视图解释为“分类维度”，用“消费类别：餐饮 / 交通”示例；每个维度就地添加、重命名和归档标签。系统名放高级详情。首先补齐上一轮确认的缺失管理动作。

### 候选复核

证据、来源、原始字段和撤销能力是优点，详情的“关闭”也经实测不会改变候选。但列表上同时展示三种转移批量操作，尚未选择任何项也全部保持可点；每个决定都用相同深蓝按钮，按钮中塞满后果说明；状态使用英文内部值。

建议：先展示类型、中文状态和关键差异；批量工具在选中后出现，显示选择数量。主操作保持简短，把后果放在决策区相邻说明中。保留原始字段默认展开这一既有需求；整理版面不应擅自隐藏已要求的证据。

### 数据库观察

技术诊断页直接暴露表名、字段类型和索引，对开发维护有用。问题在于和日常账务入口同级，且默认优先显示很长的结构表，查看行内容要继续往下找。

建议：可以在“高级工具/诊断”中保留该能力，让业务导航更聚焦。这是信息架构建议，会改变当前“五个一级入口”的明确需求，需要在后续需求修订中确认；本轮未调整导航。

## 视觉与可访问性

- 深蓝按钮用于关闭、保存、筛选、清空、详情、批量操作和财务决定，主次区分不足。应区分主操作、次操作和文本链接，不必为每种行为引入一种颜色。
- 小屏导航只剩 `[ ≡ ]`、`[ ↓ ]`、`[ ¤ ]` 等符号；有 title/aria-label，对鼠标悬停和辅助技术有所帮助，但触屏用户缺少可见名称。
- 手机候选操作按钮实测约 37px 高，常用按钮约 39px 高，拥挤区域容易点错。建议采用更宽松的触控尺寸和间距；这里不作正式标准合规判定。
- 标签弹窗有可见标题，但未设置 aria-label 或 aria-labelledby。输入标签大部分关联正常，导入文件和密码缺少明确 label 关联；密码依赖 placeholder 提示。
- 页面中嵌套两个 main，地标结构应整理。未进行屏幕阅读器实测，不把这些 DOM 观察写成已验证的朗读障碍。
- Escape 能关闭标签弹窗，焦点会回到原“选择标签”按钮；这是本轮确认可保留的行为。
- 740px 截图中侧栏内容不在顶部；768px 处筛选布局突然变化，数据库页整页宽度达到 1447px。断点切换需要覆盖临界宽度，而不只验证手机和全屏桌面。

## 建议的修改与验收顺序

1. 先修影响执行正确性的问题：切换文件后预览失效、候选筛选、重复翻页监听、保存失败保留输入、加载失败提示。
2. 补日常操作闭环：标签维护、导入结果明细、已排除流水查看、返回时保存查询状态。
3. 重排页面：流水优先，导入和高级筛选按需展开；小屏候选使用卡片；统一断点、按钮层级和中文状态。
4. 最后补概览效率：汇总时间范围、金额下钻、待复核入口和趋势可视化。

验收以操作结果为准：当前选中的文件必须等于确认提交的文件；失败后不丢输入；后退回到上一页；返回保留筛选；翻页看见新页首条；390/740/768px 下控件不能互相遮挡；已处理记录能按中文状态找回。
