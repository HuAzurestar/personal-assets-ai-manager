# UI/UX 复审：超宽屏、长屏与操作成本

## 结论与边界

目前达到基础可用，但尚不适合高频整理账目，尤其缺少超宽屏工作区组织、连续编辑和风险分级。换主题不能解决这些结构问题。

本轮只审查，不修改应用代码或账目。使用真实 Edge 无头浏览器操作运行于 127.0.0.1:8767 的示例账本，覆盖六页、十种 CSS 视口。所有非读取 API 请求均被浏览器拦截并模拟成功；一键转移测试额外将响应中的候选状态模拟为待处理。因此交互提交时机和页面跳转为实测，但不代表本轮验证了后端写入正确性。

视口：1440×900、2560×1080、2880×1080、3440×1440、3840×1440、5120×1440、1920×600、1080×2560、900×2400、390×1000。3440×1440 为约 2.39:1 的对照；2880×1080、3840×1440、5120×1440、1920×600 均大于 2.5:1。纵向长屏单独覆盖。实际体验还受系统缩放、浏览器缩放和物理屏幕尺寸影响，不能仅按面板像素推断。

60 个页面/视口组合未发现整页横向溢出，也未捕获未处理 JS 错误；这不等于不存在局部滚动、误操作或业务错误。

## 优先问题

### P1：超宽屏导航与工作区分离

- `.workspace-main` 最大宽度 1600px，居中于剩余区域；216px 侧栏固定在屏幕左缘。
- 3840px 宽时主区域起点 x=1228，侧栏到主区域之间空出 1012px；5120px 宽时空出 1652px。1600px 包含内容内边距，实际内容更窄。
- 大量宽度闲置，同时导航、数据和操作的视线/鼠标往返距离增加。不是文字必须撑满屏幕，而是导航不应与工作区脱节。
- 建议：将导航和主内容作为整体组织；账本/复核采用列表与详情并排，设置页保持可读宽度。不能简单取消所有最大宽度，让表格列无限拉开。
- 位置：`src/frontend/css/ledger.css:202`。

### P1：保存打断连续操作

- 点击列表末行标签，模拟保存成功后 scrollY 从 1387 变为 0；需要重新找回正在处理的记录。
- 原因是所有成功 render 均滚动至页首，适用于翻页的行为被复用于保存、复核等操作。
- 建议：翻页/新查询可以回顶部；行内修改保持滚动、焦点和当前记录，复核后定位下一条或原位置。
- 位置：`app/static/ledger.js:248`、`:624`、`:738`。

### P1：批量操作远离选中项，表头和分页也不常驻

- 1920×600 末行勾选后，批量栏位于视口 y=-1134，完全不可见。用户会不知道下一步去哪操作。
- 20 条桌面流水的分页在文档约 y=1850；390px 手机端在约 y=4464。表头、筛选、分页与当前阅读位置分离。
- 建议：选中时显示固定/粘性批量栏，明确“本页选中 N 条”、取消选择；表头固定，分页保持易达。跨页是否保留选择必须明示，不能偷偷清空。
- 位置：`src/frontend/css/ledger.css:483`、`app/static/ledger.js:211`、`:412`。

### P1：影响统计的重要决策太容易提交

- 模拟待复核候选上点击“个人转移”，一次点击即发送 POST `/api/candidates/2`，没有确认弹窗。保留 A/B、批量转移也直接调用提交逻辑。
- 已有说明和撤销，这是优点；但同等外观的多个按钮仍容易误点。“可撤销”提示本身没有撤销按钮，待复核过滤下记录可能消失，需要去其他状态找回。
- 建议：单条提供紧邻的影响预览与直接撤销；批量以及排除汇总操作增加一次明确确认，列出组数、记录和统计影响。不要给所有轻操作都加确认。
- 位置：`app/static/ledger.js:440`、`:528`、`:738`。

### P1：低高度视口被表单占满

- 1920×600 默认首行 y≈430；展开高级筛选后首行 y≈656，首屏完全没有流水。
- 大标题、说明、边距和筛选累计消耗高度；CSS 主要按宽度分段，缺少低高度处理。
- 建议：压缩页头，日期/常用标签快捷筛选常驻；高级筛选用侧面板或紧凑区域，应用后收起并显示已应用条件。提供舒适/紧凑密度，而不是缩小全部文字。
- 位置：`src/frontend/css/ledger.css:644`、`app/static/ledger.js:347`。

### P2：竖向长屏的布局断点不合适

- 900×2400 仍保留 216px 桌面侧栏，主区仅 684px；每行“详情/标签”堆叠，行高从 71px 升至 113px，日期和交易方换行。
- 分页因此从文档约 y=1850 下移到 y=2682。虽然没有横向溢出，却需要更多滚动和逐行对齐。
- 建议：依据主内容可用宽度切换紧凑导航/列表布局，而不是只看整个窗口是否低于 850px；保留用户手动展开导航能力。
- 位置：`src/frontend/css/ledger.css:661`。

### P2：筛选存在“看起来已生效”的状态错位

- 将收支选择为“收入”后，URL 和结果仍保持原来全部 32 条，必须再点查询；没有未应用标记。
- 主题是即点即生效、筛选却需提交，两种行为可以共存，但必须清晰区分。高级筛选又有独立“应用筛选”，增加理解成本。
- 建议：离散下拉项即时应用，或统一保留一个明确的应用入口并提示“条件已修改，尚未应用”；展示可单独移除的已应用条件，补本月/上月等快捷日期。
- 位置：`app/static/ledger.js:347`、筛选 submit 事件。

### P2：技术信息与日常任务争夺注意力

- 流水详情和复核详情默认展示 JSON 原始字段；候选卡重复显示批次、流水号、置信度、原因及多段影响说明。
- 标签管理给每行重复放置重命名和归档；数据库和日常流水同为一级入口；设置页也常驻高强调“导入账单”。
- 建议：日常层展示交易事实、差异与行动；技术证据放次级区域。注意 README 目前明确要求复核原始字段默认展开，不能未经需求调整直接移除；可以保持可见但做结构化对照与独立滚动。数据库可移入设置/高级工具。
- 位置：`app/static/ledger.js:158`、`:425`、`:720`、`:730`。

### P2：轻量分类仍偏重，批量修改缺少回退入口

- 单笔标签需要打开弹窗、选择、保存，列表中不呈现维度名（靠悬停 title）；同名标签跨维度时难以辨认。
- 批量修改已有数量和“保持原标签”保护，但当前 UI 没有此次批量修改的直接撤销入口。
- 建议：行内快速分类/侧面板连续编辑；批量提交显示修改摘要，提供可恢复的历史或撤销。保持单维度更新语义，避免覆盖未修改维度。
- 位置：`app/static/ledger.js:280`、`:624`。

## 建议实施顺序及验收

1. 先处理风险和上下文：批量确认、直接撤销、保存不跳顶、选中操作栏常驻。
2. 再处理响应式结构：导航与主区整体布局，超宽列表/详情双栏，低高度紧凑页头，长屏按内容宽度折叠侧栏。
3. 最后降低理解成本：筛选状态明确、常用日期快捷入口、原始证据分层、减少重复操作按钮。

验收应包含：3840×1440 与 5120×1440 导航紧邻工作区；1920×600 可同时看见筛选和实际流水；900×2400 核心列无需逐字换行；编辑末行后仍在原位置；任何位置勾选均能立即访问批量操作；批量排除前能看清影响且操作后能直接撤销；筛选控件与结果生效状态一致。
