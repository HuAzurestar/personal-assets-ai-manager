# 账单复核基座：当前实现与验证边界

设计依据为 PIRC-A-22《账单审查基本思想：金额分配、往来结算与可修正决定》。本轮先实现手工确认与数据约束，候选匹配质量不作为完成条件。

## 数据与操作

- `review_matters` 仅保存事项标识和当前版本；`review_matter_revisions` 保存只追加的确认、修改、撤销快照、理由、操作者及幂等请求。修改使用期望版本，旧页面不能覆盖新版本。
- 每个分项指向原始流水，按整数“分”保存金额，区分本人收入、本人费用、应收、应付、收回本金、偿还本金及本人转移。原始流水可拆多行，多笔流水可组成同一事项。
- 同一流水跨有效事项的分配总额不得超过实际金额。未分配余额显示为待解释，不自动凑平。
- 应收应付按事项、方向和往来对象分别核对。结算不能超过已记录的债权债务；尾差由用户明确修改责任份额。当前不提供自动免收、自动抵债或跨事项债务结算。
- 本人转移需要用户确认账户归属、至少两个不同账户名称、人民币收付分项严格相等。手续费独立列为本人费用。
- 同一次提交内校验并保存全部分项；`BEGIN IMMEDIATE` 串行化写入，幂等键与版本约束防止重复提交。事务内不执行外部模型请求。
- 确认的重复候选不自动扩张成员；互相占用流水的有效候选不能同时确认，批量冲突整批回滚。撤销依据剩余有效决定重算，不恢复整个旧快照。
- 新的整笔“他人转移/代收代付排除”已禁止，改由手工事项明确往来对象及本金/费用分配。历史决定保留展示和撤销，并通过历史复核告警提示核验。
- 所有流水拒绝物理删除；标签定义使用归档。规则/模型结果作为建议，人工确认不再由置信度竞争决定。标签可采用建议、修改、撤销后再次修改；批量修改有旧版本保护。

## 退款及汇总

退款性质与退款分配分别保存。确认部分退款分配会声明该正向流水的退款性质；撤销分配不会把剩余金额转成收入。误认退款时，先撤销有效分配，再在退款记录中纠正性质，历史保留。

例如支出 300、退款 100、分配 60：收入 0，支出 -300，退款抵扣 60，个人净收支 -240，未分配退款 40，实际现金净变化 -200。现金与个人收支分别展示。

当前口径为 `review-foundation-v2`：退款抵扣按退款实际发生期间统计，可以关联期外原支出。时间、来源、账户、标签等筛选作用于贡献流水；它不是把退款重新分摊到原支出月份或继承原支出标签的订单成本报表。

dashboard 与回钻共用每条流水的贡献结果：原始收付、收入贡献、费用贡献、退款抵扣、净额、待解释金额及事项关联。收入卡片不再仅跳转到所有正向流水。

未建立金额解释的普通流水仍沿用账单方向暂计，页面显示其数量；未分配退款、未解释事项金额和历史冲突单独提示。存在这些事项时不能把数字称为最终核定结果。

## 导入质量

解析器不再静默跳过缺少时间的交易行，不把缺少方向的正金额猜作收入，不从混杂字符中抽取数字凑成金额。异常交易状态及非人民币币种进入待核验。

确认导入时，单文件事务同时保存来源指纹、正常流水与错误行证据。错误行保存到 `import_row_issues`，修正前不产生正式金额；文件重复或数据库约束/写入失败不留下部分提交。批量文件之间独立提交。

预览显示正常数、问题行及原因；确认后提示待核验数。用户可以补充实际收付字段及理由生成流水，原始 JSON 和行号不变；也可确认为非实际人民币收付，并重新打开核验。`import_issue_actions` 保留这些动作的追加审计。

已通过人工修正生成的流水仍受事实删除保护。当前没有对已经入账的时间、金额任意重写的入口；应在确认修正时核实原始平台证据。

## 界面入口

- 概览、流水、复核页：手工事项与往来、退款记录、数据问题。
- 流水页：选中记录后“建立手工事项”；事项中可搜索其他流水、拆分金额、修改关联、查看历史、撤销或重新确认。
- 流水详情：修订账户及撤销历史、标签建议/确认/撤销、确认退款性质。
- 退款记录：关联原支出、按分配记录撤销、查看审计、纠正退款性质。
- 概览指标：查看实际贡献金额及事实/修订依据。

## 明确限制

- 当前仅支持人民币两位小数。新写入拒绝非有限数值、超范围及超过两位小数的金额；不自动舍入原始金额。旧 Bill/RefundAllocation 列保持兼容存储，计算及校验转换为整数分，新事项直接保存整数分。
- 原账本中的旧决定不自动重写；发现重叠占用或旧整笔第三方排除时提示核验。修复应通过明确撤销和重新分配进行。
- 退款目前仍使用独立的分配模型。涉及有效手工事项的流水与退款分配相互阻止，避免把 AA 退款错误地全部抵扣本人费用。组合 AA 退款、多币种、代扣税明细和跨事项抵债没有假装实现。
- 应收应付需要同一事项中的实际收付或垫付记录；仅有口头借款、朋友付款等未出现在本人账单中的义务，尚无独立业务证据录入入口。
- 尚无智能自动纠错、长期自动确认、自动匹配费用差额或更复杂的建议算法。

## 验证

后端回归：`python -m pytest -q`。`tests/test_review_foundation.py` 覆盖金额占用、AA 部分结算及尾差、一对多改关联、版本冲突、并发写入、退款跨期/单笔撤销/性质修正、候选冲突与批量回滚、标签建议和撤销、脏数据修正及事实保留。

安装独立的 Playwright 后执行：

```powershell
python scripts/verify_ui.py
python scripts/verify_review_ui.py
```

两份浏览器脚本均启动临时账本，不连接已有服务或真实数据库。Windows 使用已安装 Edge；其他平台需安装 Playwright Chromium。新增脚本覆盖真实手工事项创建/纠错、失败输入保留、退款确认/分配/撤销、金额回钻、问题行修正及窄屏操作。

测试通过表示已覆盖的契约满足，不等于对所有未知账单和组合场景承诺零缺陷。
